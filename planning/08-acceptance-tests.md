# 08 · 各阶段验收标准与测试方案

> 交付物对应：阶段 0 要求的「9. 各阶段验收标准与测试方案」
> 结构：第 1 节测试策略；第 2 节分阶段验收清单（编号 A<阶段>-<序号>，07 文档任务与 01 文档需求均回链此处）；第 3 节最终验收（方案·六 15 项检查表落地）；第 4 节测试环境与数据；第 5 节缺陷处理。
> 每条验收采用四要素：**给定条件 / 执行操作 / 预期结果 / 证据形式**。数值阈值未在规格中定义时按行为断言验收（任务编排规则："不擅自写成两秒内"）。

---

## 1. 测试策略（分层）

| 层 | 工具/方式 | 覆盖对象 | 执行时机 |
|---|---|---|---|
| 单元测试 | pytest（服务层：WBS 编码/依赖环/进度汇总/评分规则/快照；前端 Vitest 表单与确认流组件） | 04 文档 DM 决策、TD-01/02、BR-01~05 | 随任务，进阶段验收 |
| API 集成测试 | pytest + httpx（独立测试库，每用例自建种子） | 校验分支、边界、跨项目隔离、错误结构 | 每阶段任务完成 |
| 前端构建验证 | `tsc --noEmit` + `vite build` | 类型与可构建，防“假页面” | 每阶段任务完成 |
| E2E 抽样 | Playwright（登录后主链路） | 项目→WBS→甘特→基线→风险→AI 建议确认 | M5 后抽 5 条主链路（T6-05） |
| 部署验证 | 脚本化 compose 演练（启动/重启/备份/恢复/迁移） | NFR-02/07/11/12 | 每阶段持久化项，终验 T6-03 |
| 人工验收 | 用户按本清单操作 | 视觉、文案、体验项 | 每阶段验收会话 |

**贯穿原则（方案·阶段6原文）：对所有失败的测试进行定位和修复，不能伪造通过结果；不以页面数量、代码量或 Agent 自我评价为验收依据。**

总验收门槛（方案·六原文）：以干净环境中的**实际部署和业务测试**为准，不以页面数量、代码量或 Agent 自我评价为准。

## 4. 测试环境与数据

- 后端集成测试库：`postgresql` 独立库，每用例事务回滚或种子重建；测试不依赖任何线上数据。
- 种子数据集（验收演示用，可脚本重建）：1 个跨 3 个月的信息化交付项目、3 级 WBS 25+ 任务、依赖含合法与待拒环、2 基线、10 风险（高中低混合）、6 问题（含 2 待关）、1 干系人组、1 交付清单（按模板）、7 天进度快照。
- 异常网络模拟：AI 适配层用本地 mock server 复现超时/5xx/非 JSON（仅测试装置，产品中禁止模拟 AI 输出——S-5）。

## 5. 缺陷处理

1. 验收发现缺陷 → 记录（编号/阶段/复现/责任人=TeleAgent/严重级）；不通过项不关闭阶段。
2. 修复后补测原用例 + 关联用例（防“改好 A 坏 B”）；两次回归通过才销项。
3. 阶段报告中披露已知问题与修复计划（阶段6“已实现、未实现和已知问题清单”的前置），不允许静默修复不留痕。
