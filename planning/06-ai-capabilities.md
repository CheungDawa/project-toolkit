## 1. 第一版 AI 能力清单（阶段 4 提示词原文六项）

| # | 能力（原文） | 输入上下文 | 产物形态 | 关联任务 |
|---|---|---|---|---|
| AI-1 | 根据项目描述生成 WBS 初稿 | `projects.description` + 名称/阶段/计划起止 + 用户补充要求 | `ai_action_proposals(action_type=wbs_draft)` 差异预览：拟新增任务树（多级） | T4-07 |
| AI-2 | 根据项目范围、任务计划和约束条件辅助检查工期及任务依赖 | 当前 `tasks`（日期/工期/依赖）+ 工作日历 | 对话内分析结论 + 定位到具体任务的建议（不直接改数据） | T4-08 |
| AI-3 | 根据风险台账、问题台账和进度偏差提出风险建议 | `risks`+`issues`+快照偏差摘要 | 对话建议（引用具体风险/问题/约束作为依据——TD-03） | T4-09 |
| AI-4 | 根据项目真实数据生成周报初稿 | 任务完成量/进度/风险/问题现状汇总 | 待编辑草稿；头部强制标注统计截止日期、数据来源、生成时间；缺失项显式"信息不足"标注 | T4-10 |
| AI-5 | 根据交付资料清单检查缺失项并生成补齐建议 | `deliverables` 状态 × 模板 | 建议列表（**实施排至阶段 5，因依赖交付资料模块先存在**——矛盾点 C-3 处理，见 09 文档） | T5-08 |
| AI-6 | 提供项目管理问答，引用当前项目真实字段和记录 | 项目上下文自动装配（见 2.1 数据最小化） | 对话回答；无数据时明确"信息不足"，不得推测充当事实 | T4-11 |

共同机制（源自阶段 4 提示词实现要求，逐条落实）：

- 结构化输出解析为**经过验证的结构化 JSON**；任务名称、日期、负责人、依赖关系等字段做业务校验 → 校验失败不成建议（T4-04）。
- 建议先存 `ai_action_proposals`，展示增量/修改/删除差异；用户确认后写入业务表（BR-05，T4-05）。
- 高影响操作（删除项目、批量改期等）单独确认；模型永无直接执行权（T4-06）。
- 不把 AI 推测当项目真实数据（BR-G1）；无数据时明确提示信息不足。
- 模型不可用/超时/格式错误 → 可理解的错误提示与重试（NFR-10，记录 `call_status`）。
- API 密钥停留在服务端（NFR-05）；对发送给外部模型的项目数据执行**数据最小化**并向用户说明发送范围（TD-03 / NFR-06）。
- 记录 AI 调用状态、生成时间、模型标识和人工确认结果（T4-12）。
- 允许用户编辑 AI 生成内容——编辑发生在接受前的建议草稿层。

## 2. 数据流

```
【上下文装配】                 【服务端适配层】              【结果处理】
业务表(真实数据)                 model.default 配置            解析 JSON
      │ (仅调用所需字段,            │ Provider/base/model         │ 结构校验(schema)
      │  数据最小化白名单)  ──────▶ │ api_key 仅服务端     ──────▶ │ 业务校验(日期/引用/类型)
      │                           │ timeout/retry        结果    │
      │  context_digest 记录 ─────▶ │ (OpenAI 兼容协议)    返回    ▼
      │  (本次实际发送范围)         │                            待确认建议
      │                           │ 失败→call_status=             ai_action_proposals
      │                           │ timeout/api_error/          (status=pending)
      │                           │ format_error                 │
      │                           │ + 前端错误提示与重试          ▼
      │                                                        人工确认(可编辑;高影响再确认)
      ▼                                                        │ accept
  ai_messages(对话历史)                                        ▼
  ai_action_proposals ───────────────────────────── 服务层事务写入业务表
  activity_logs(accept_ai/reject_ai + 时间/模型/确认人)         + activity_logs
```

### 2.1 上下文装配与数据最小化（每能力白名单）

| 能力 | 发送给模型的数据白名单 | 明确不发送 |
|---|---|---|
| AI-1 WBS 初稿 | 项目名称、描述、阶段、计划起止、用户附加要求 | 现有任务/风险/干系人/附件内容 |
| AI-2 工期依赖检查 | 任务树摘要（wbs_code/名称/日期/工期/依赖对），项目工作日历参数 | 附件、沟通记录 |
| AI-3 风险建议 | 风险台账（不含责任人联系方式）、问题台账、进度偏差摘要 | 干系人诉求全文（含个人信息多）默认不发——TD-03"客户信息发送前可控范围" |
| AI-4 周报 | 上述数据的聚合结果（非明细原文） | 附件二进制、密钥、无关键数据 |
| AI-6 问答 | 按提问检索装配：项目/任务/风险/问题/交付清单字段值 | 全库倾倒；未询问的对象不发 |

每次调用的实际发送范围存入 `ai_messages.context_digest`（JSON：能力类型 + 字段清单 + 截至时间戳），并在 AI 工作台向用户明示（"向用户说明发送范围"——NFR-06；用户可在设置中看到并在能力级开关里关闭某类发送，第一版实现能力级白名单即可满足规格）。

## 3. 安全边界（红线清单）

| # | 红线 | 实现机制 | 验收锚点 |
|---|---|---|---|
| S-1 | API 密钥不发送到浏览器、不写入前端代码、不进普通日志 | 密钥仅存服务端 `app_settings`（加密）；接口返回时脱敏显示 `sk-****后4位` 或完全不回显；任何日志实体过滤密钥模式 | A4-8（浏览器开发工具看不到密钥） |
| S-2 | 模型无直接执行权；不因返回内容格式"合法"就自动落库 | 唯一写入路径 = 用户点击接受 → 服务层事务（含高影响二次确认） | A4-6（未经确认 AI 不能改业务数据） |
| S-3 | 无效 JSON、非法日期、不存在的任务引用不能写入正式数据 | 解析→schema 校验→业务校验三层过滤；失败入 `call_status=format_error` 并提示重试 | A4-4 |
| S-4 | 未配置模型 → 非 AI 功能全部可用（降级不连坐） | AI 模块独立配置检测；路由级 feature check | A4-3 |
| S-5 | 不得用固定回复或随机数据模拟 AI | 验收以实际配置后的真实调用为准（方案·阶段4末段） | A4-1 |
| S-6 | 周报仅引用真实数据，缺失信息标注 | 聚合器只读业务表；报告头部含统计截止日期/数据来源/生成时间 | A4-7 / TD-03 |
| S-7 | 提示注入防护的最低要求：AI 返回中的"指令"不解释为系统操作 | 解析层只接受白名单字段，不执行返回中夹带的"额外命令"；diff_preview 只读展示 | 并入 A4-4 测试用例 |
| S-8 | 本地数据不出域的可选模式 | 适配层 Provider 抽象允许未来指向本地推理服务（保留能力，方案·一） | 架构位保留，本期不实现（不虚报能力） |

## 4. 调用状态与可追溯性（TD-03 落地）

每次 AI 交互在 `ai_messages` 落：`call_status`、`model_identifier`、`created_at（生成时间）`、`context_digest（发送范围）`；建议接受/拒绝在 `activity_logs` 落 `accept_ai/reject_ai`（含确认人与时间）。周报草稿首行固定输出：

```
统计截止日期：YYYY-MM-DD ｜ 数据来源：Project Toolkit（任务/风险/问题/交付清单聚合）｜ 生成时间：YYYY-MM-DD HH:mm ｜ 模型：xxx
```

WBS 初稿的差异预览保留在 `ai_action_proposals.diff_preview`，用户接受前后记录可复查（"WBS 初稿应能查看生成前后的差异"——方案·细节3）。风险建议在对话中显式引用依据对象编号（"依据任务 T3.2、问题 I-5"）。
