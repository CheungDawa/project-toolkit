# WBS Studio 升级方案（任务书二）：诊断与实施计划

日期：2026-10-12　状态：方案待确认（尚未实施）

## 一、规格来源

任务书二要求把 WBS 页升级为专业级工作分解结构设计器：
1. 三视图协同：React Flow 树形图 + 专业树形表格 + 节点详情面板
2. 节点类型模型：根 / 阶段 / 子系统 / 交付物 / 工作包 / 执行任务 / 里程碑，可配置
3. 10 类项目模板库
4. 版本管理：版本对比 / 恢复 / 撤销 / 重做
5. Excel 导入导出、高清图片、PDF 导出
6. 数百节点性能
7. 不得破坏现有甘特图 / 风险 / 交付等模块的数据一致性

## 二、现状诊断（2026-10-12 代码核查）

| 需求 | 现状 | 差距 |
| --- | --- | --- |
| 三视图 | WbsPage 仅树形表格（antd Table 展开树 + 编辑弹窗） | 缺 React Flow 图视图与常驻详情面板 |
| 节点类型 | Task 无类型字段，全部平铺任务 | 需新增 `node_type` 列 + 类型配置 |
| 模板库 | 无（deliverable-templates 是交付物模板，概念不同） | 新建 WBS 模板机制 |
| 版本管理 | 有"计划基线"（ScheduleBaseline + 快照 + diff），无结构版本/恢复/撤销重做 | 扩展或新建版本机制 |
| Excel 导入导出 | 已有 `tasks/export`、`tasks/import`（openpyxl） | 补节点类型列，改造量小 |
| 图片/PDF 导出 | 无 | 新增 |
| 性能 | 前端树形 Table 一次性渲染，未实测数百节点 | 需实测 + 图视图虚拟化 |

约束与风险：
- **数据一致性（需求 7）**：Task 表被甘特图、看板、燃尽图、快照、报告、交付物关联消费。加列必须可空 + 默认值兼容历史数据；所有既有 API 响应结构不变（只增字段）既有 69 测试须全绿。
- **里程碑类型映射**：里程碑目前是独立 `milestones` 表（有独立页面/甘特图联动）。节点类型模型把"里程碑"作为 WBS 节点类型。方案采用**双轨**：node_type=里程碑的任务在 WBS 内展示里程碑样式并可联动创建 milestones 记录（方案 A：里程碑节点保存时同步 milestones 表），不删除既有页面。
- **新依赖**：`@xyflow/react`（React Flow v12，官方类型）需经国内镜像拉取；构建门禁 `tsc --noEmit` 全绿。
- **撤销/重做**：采用前端操作栈（结构操作记录逆操作参数，按 Ctrl+Z/Y 重放 API），不做后端事务日志（复杂度过高，先保功能闭环）。

## 三、待澄清事项（开工前确认）

1. **AI 复用**：任务书提到"复用现有 AI 服务层"，但 AI 模块已按用户指示移除。默认方案**不含 AI 能力**；如需模板智能推荐等，须重新确认是否恢复部分 AI 基础。
2. **版本管理与既有"计划基线"关系**：默认**新建独立 wbs_versions**（结构版本），不改既有基线功能，避免污染已验收模块。
3. **10 类模板清单**：默认按电信集成项目背景拟定：①通用软件研发 ②弱电集成 ③安防工程 ④网络割接 ⑤机房建设 ⑥维保服务 ⑦数据迁移 ⑧验收专项 ⑨培训交付 ⑩咨询规划。可替换。
4. **PDF 导出**：默认采用浏览器打印 CSS 分页 + 图视图白底渲染（零新后端依赖）；如需服务端 PDF 再确认。

## 四、批次与任务编排

工作量区间为单人角色（开发）净工时估算。

### 批次 A：节点类型模型（2–4h）
- A1 迁移 0010：`tasks.node_type`（可空字符串，默认空=按现有语义处理）+ 约束
- A2 类型配置常量（前端）+ `app_settings.wbs.node_types`（后端可配置，默认七类）
- A3 TaskCreate/TaskUpdate/TaskRead 增字段；表格视图类型徽标与里程碑日期列
- 验收：历史项目打开不报错、69 测试全绿 + 新增类型用例

### 批次 B：React Flow 树形图 + 三视图（6–10h）
- B1 引入 `@xyflow/react`；自定义节点组件（按类型着色/图标/里程碑菱形）
- B2 树形自动布局（dagre 或手写 dfs 层级布局）；fitView；选中联动表格与详情面板
- B3 节点交互：新增子节点/删除/改名（复用现有 API）；图上拖拽改父级（复用 reorder API，拒绝环已是后端行为）
- B4 性能选项：`onlyRenderVisibleElements`、节点折叠（子树隐藏）；500 节点生成脚本实测
- 验收：三视图选中同步；500 节点下操作无明显卡顿（主观流畅 + 首屏 < 3s）

### 批次 C：模板库（4–6h）
- C1 模板数据模型：`wbs_templates`（JSON 结构：节点名/类型/默认工期/层级）+ 管理 API（列表/创建/更新/删除）
- C2 内置 10 类模板（种子数据，代码内置常量，管理页可改）
- C3 从模板实例化：创建项目时可选模板 → 批量生成 WBS（事务，失败全回滚）；复用现有批量创建逻辑
- 验收：从"网络割接"模板建项目生成完整结构；模板 WBS 编码正确

### 批次 D：版本管理（6–10h）
- D1 `wbs_versions` 表：版本号/名称/快照 JSON/tasks 快照（沿用 0004 基线模式）；创建/列出/删除 API
- D2 版本对比：结构 diff（新增/删除/移动/改名/类型变更），前端对比视图（左右或行内标记）
- D3 恢复：选中版本重建 WBS（事务替换，审计日志留痕）
- D4 前端撤销/重做：结构操作栈 + Ctrl+Z/Y + 工具栏按钮；边界（刷新后失效，如实提示）
- 验收：改 3 处结构 → 存版本 → 再改 → 对比正确 → 恢复 → 撤销重做可用；审计日志有记录

### 批次 E：导出增强（3–5h）
- E1 Excel 导入导出补 node_type/里程碑日期列（兼容旧文件）
- E2 高清 PNG：React Flow toImage（2x/3x 缩放，白底）
- E3 PDF：打印样式分页 + 版本信息页脚（浏览器打印，含表格视图分页）
- 验收：导出 PNG 清晰可辨；Excel 往返不丢字段

### 批次 F：回归与验收（2–3h）
- F1 全模块回归（甘特/看板/基线/燃尽/报告/交付）
- F2 500 节点压力实测记录 + 验收报告 `18-taskbook2-report.md`

合计估算：**23–38h**（单人）。

## 五、依赖顺序与并行
