> 交付物对应：阶段 0 要求的「4. 页面导航与交互流程」
> 信息架构参考：Plane 的现代工作台布局（左侧导航-项目-视图切换，仅借鉴交互，见 02 文档 2.2）；模块入口以本规格 P0/P1 范围为准。

## 1. 信息架构（中文 PC Web，NFR-01）

```
左侧导航（固定，可折叠）          顶部操作区（面包屑 + 页面标题 + 主操作按钮）
├─ 工作台（项目列表 / 汇总）       ┌──────────────────────────────────┐
├─ 项目（进入项目空间）           │  内容区（表格 / 图表 / 表单 / 弹窗） │
│   ├─ 概览                       └──────────────────────────────────┘
│   ├─ WBS 任务
│   ├─ 甘特图
│   ├─ 里程碑
│   ├─ 基线
│   ├─ 风险(P0)
│   ├─ 问题(P0)
│   ├─ 变更
│   ├─ 干系人(P1)
│   └─ 交付资料(P1)
├─ AI 工作台（跨项目对话与建议确认）
└─ 设置（模型配置 / 工作日历 / 评分规则 / 报告与清单模板）
```

导航规则（源自规格的硬要求）：
- 未实现的模块入口**标注"待开发"且不可点击**，禁止假按钮（NFR-03，阶段 1 验收项）。
- 项目空间内的模块共享同一项目上下文；跨项目数据不出现在当前项目视图中（阶段 3 验收："不同项目的风险、问题和干系人数据不会错误串联"）。

## 3. 关键交互流程

### 3.1 项目创建（T1-09）

```
点击"新建项目" → 表单（编号/名称/客户/项目经理/阶段/状态/计划起止/描述）
  ├─ 编号重复       → 提交时 422+字段级错误（后端唯一校验为准，前端仅预检提示）
  ├─ 计划止期 < 起期 → 日期字段级错误（"非法日期有明确提示"——阶段1验收）
  └─ 保存成功 → 跳转项目概览，activity_logs 记录 create
删除：二次确认弹窗（明示影响：项目下属数据范围），确认后软删+审计（阶段1提示词·条5"删除确认流程"）
归档：不删数据，仅置 archived_at；归档项默认从列表隐藏但可筛选（NFR-02 持久化基调）
```

### 3.2 WBS 编辑 → 甘特同步（BR-01，T2-11/T2-12）

```
WBS 树表格改计划日期 → 乐观更新行内视图 → PATCH /tasks/:id
  ├─ 服务层校验（依赖环/日期越界/非法工期）失败 → 拒绝并回滚，错误定位到字段
  └─ 成功 → 返回重算后的 wbs_code 与父任务汇总 → 概览/甘特数据源同一接口
甘特图拖拽条 → snap_at 捕捉 → 触发变更事件 → 同一 PATCH 端点（与桌面编辑共用校验路径）
  ├─ 校验失败 → 甘特回弹至原位置 + toast 错误
  └─ 成功 → update_task 局部刷新；基线若已冻结，仅当前计划变化（BR-02）
```

### 3.3 保存基线与对比（BR-02，T2-13）

```
基线页点击"保存当前计划为基线" → 命名 + 冻结时间 → 事务内复制全量任务计划字段到
baseline_task_snapshots → 之后任何 WBS/甘特修改只写 tasks 表，基线表只读。
对比视图 = 逐任务 diff（当前 vs 所选基线），差异列高亮；只读展示，不提供"改基线"入口。
```

### 3.4 风险 → 问题/任务转化（BR-04，T3-08）

```
风险详情页 → "转为问题" → 创建 issue（risk_id 回链）→ 原风险状态置"已转问题"
但记录保留、可打开、评估历史仍在 → 回答"不能因为转化就丢失原始风险记录"。
（转任务同理：创建/关联某任务，风险状态置"已转任务"，归档不删除。）
```

### 3.5 AI 建议确认流（BR-05 + 方案·阶段4，T4-05/T4-06）

```
AI 生成（如 WBS 初稿）→ 解析为结构化 JSON → 服务层业务校验
  ├─ 校验失败（非法日期/不存在的任务引用/无效 JSON）→ 不入库不展示为建议，提示重试（阶段4验收）
  └─ 通过 → 存 ai_action_proposals(status=pending, diff_preview=新增/修改/删除)
       → 用户在建议中心看差异（可编辑 AI 生成内容——阶段4实现要求"允许用户编辑"）
       → 点击"接受" → 高影响操作（删项目/批量改期）再次单独确认
       → 服务层事务写入业务表 + activity_logs 记录 accept_ai
       → "拒绝"仅置 rejected，业务表零改动；未确认前任何业务表不出现该建议数据。
```

### 3.6 问题关闭（T3-07）

```
问题详情 → "关闭问题" → 若 closure_result 为空 → 表单强制聚焦必填"解决结果"（阻止提交）
→ 保存后状态已关闭 + verified_at/by 记录；关闭后仅允许追加备注，不允许改根因与处理措施（保历史）。
```

### 3.7 未配置模型时的 AI 页行为（NFR-04，T4-13）

```
/app_settings 无 model.default → AI 工作台显示配置引导（跳设置页）
其余全部功能（项目/WBS/甘特/风险/问题/导出）不受影响；文档在页内说明当前发送到模型的数据范围（TD-03）。
```

## 4. 全局交互规范（源自规格验收条款）

| 规范 | 来源 |
|---|---|
| 刷新页面/重启容器后数据仍在（不用浏览器状态存业务数据） | NFR-02 |
| 空状态下显示引导用语而非图表（无历史快照不画假曲线） | BR-03 + 阶段5验收"新建项目无历史快照时应显示空状态" |
| 错误提示可理解、可定位到字段；网络/超时给重试入口 | NFR-10 + 阶段4实现要求 |
| 表格默认密度紧凑、中文文案、日期格式统一 `YYYY-MM-DD` | NFR-01；frappe-gantt 传 ISO 串 |
| 二次确认仅用于不可逆或高影响操作（删除/接受 AI 高影响建议），普通保存不弹确认 | 方案·阶段4"对高影响操作要求明确确认" |
